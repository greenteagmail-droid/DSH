# 屏幕记忆与提问窗

这是本分支**唯一保留的两层能力**：静默记录 + 需要时回看 + 提问窗。

「实时陪看」（`watch` / `peek` / `scene` / 常驻唤醒 / 帧插话 / 4×4 拼图）已经全部删除。
原因很实际：它会自己往会话里投消息、和提问窗抢同一条聊天流、持续烧 token。

---

## 一、它现在做四件事

| 能力 | 入口 | 说明 |
|---|---|---|
| **静默记录** | `bionic({action:"record"})` | 12fps 采样；静止 1 帧/秒，动着 4 帧/秒；**固定 1920×1080** JPEG；同时写 OCR 文字索引（本地算，零 token） |
| **本地候选** | `bionic({action:"list"})` | 按下麦克风**前 5 秒**的候选帧：时间 / 窗口 / OCR 片段 / `frame` id；不带图 |
| **取那一张** | `bionic({action:"look", frame:…})` | 只取 `list` 里确定的那一张，1920×1080 ≈1224 token；一次一张、一轮一张 |
| **提问窗** | 悬浮窗输入框 / 麦克风 | 你打的字、说的话 → `chat.jsonl` → 叫醒模型 → 回看 → 用 `say` 回答 |
| **语音播报** | `say` | 内置 Windows SAPI，装完即有声音，无需配置 |

---

## 二、数据流

```
采集 12fps ──► pipeline（sink 模式：只留帧，不拼图）
                 │
                 ├─► memory.js：1920×1080 JPEG 落盘 + index.jsonl + OCR 文字索引
                 │        └─► 5GB / 7 天，谁先到按谁删
                 │
                 └─► 窗口 chat.jsonl ◄── ask.js 轮询 ──► 叫醒模型
                                                          │
                            list（本地候选，零 token）◄────┤
                                                          │
                            look（取 1 帧 1920×1080）◄────┘
                                     │
                              say ──► SAPI 朗读 + replied.at（窗口解锁麦克风）
```

窗口里说的话只走 `chat.jsonl`；模型的回答只走 `say`（语音 + 窗口气泡），
**不再往聊天流里写 assistant 行** —— 两份「说过什么」会互相打架。

## 四、参数

### 记录（`src/record.js`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `fps` | 12 | 采集帧率；节拍按 0.25 秒算，必须是 4 的整数倍才好对齐 |
| `cadenceSec` | 0.25 | 画面在动时的落盘节拍，4 帧/秒 |
| `idleCadenceSec` | 1 | 画面静止时的落盘节拍，1 帧/秒（在 `pipeline.js` 的 `DEFAULTS`） |
| `idleRatio` | 0.002 | 变化采样点占比低于它算静止，0.2% 约四个鼠标指针 |
| `motionStride` | 8 | 比对采样步长，每多少个像素取一个点 |

### 比对（`src/motion.js`）

相邻两帧按步长取点比较，给出「变化的面积占比」。一个 32×32 的鼠标指针约占 0.05%，
光标从一处挪到另一处约 0.1%；打一行字、滚一屏都远大于 1%。1920×1080 下每帧比对
约 0.2 ms，12fps 时占单核 0.23%。

### 存储（`src/memory.js` 的 `DEFAULTS`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `storeWidth/Height` | 1920×1080 | 存图分辨率，固定这一档，不跟屏幕走 |
| `jpegQuality` | 4 | ffmpeg 的 mjpeg 质量 |
| `ttlMs` | 7 天 | 过期删除 |
| `maxBytes` | 5GB | 容量上限；和 7 天两个条件谁先到按谁删 |
| `ocrMinGapMs` | 250 | 每帧都认；设大就降 CPU |
| `ocrScale` | 2 | 识别前放大倍数（实测把错误率从 26% 压到 11%） |

### 识别

| 参数 | 默认 | 说明 |
|---|---|---|
| `frame` | 无 | **必填**。`list` 给出的毫秒时间戳，必须是识别窗口内的候选 |
| `keyword` | 空 | 只用于 `list`：按 OCR 文字模糊筛候选 |

识别范围固定是**按下麦克风前 5 秒**（`~/.dsh/bionic/mic.start` 那一刻往前推）；
输出固定 1920×1080，一次一张，一轮一张。没有 `limit` / `minutes` / `where` / `detail`。

## 五、进程生命周期

窗口是插件用 `detached` 拉起来的独立 Python 进程。**Windows 没有「父进程死了子进程跟着死」**，
所以必须自己管：插件把宿主 pid 通过 `DSH_PARENT_PID` 传给窗口，窗口每 2 秒问一次
「宿主还在吗」，不在就自己退出（实测 2~5 秒内消失）。

| 场景 | 谁负责 |
|---|---|
| 正常退出 / 插件卸载 | 卸载钩子里 `closeWindow()` 直接杀 |
| DSH 被强杀、崩溃 | 窗口里的 watchdog 自己退 |

记录器（ffmpeg）是插件的子进程，宿主一退管道断掉，它跟着结束。

## 六、插件之外的东西（为什么不在插件里）

| 路径 | 内容 | 原因 |
|---|---|---|
| `~/.dsh/bionic/models/` | SenseVoice 模型 228MB | 二进制模型，不该进 npm 包 |
| `~/.dsh/bionic/asr-venv/` | sherpa-onnx + sounddevice | Python 依赖，独立 venv 不污染宿主 |
| `~/.dsh/bionic/mem/` | 截图与索引 | 运行时数据 |
| `~/.dsh/watch-window.json` | 窗口位置、名字 | 运行时配置 |
| `~/.dsh/bionic/recording.flag` | 「上次在记」标记 | 重载后自动续记 |

**代码全在插件里**；这些只是数据和依赖。

## 六、排查

| 症状 | 先看 |
|---|---|
| 没声音 | `~/.dsh/bionic/voice.log` 有没有 `speak ok`；再看系统主音量（本机常年 16%） |
| 卡在「没听到内容」 | `~/.dsh/bionic/mic.txt` 里的 `#` 诊断行 |
| 窗口不见了 | `~/.dsh/bionic-window.pid` 指向的进程还在不在；`bionic-window.log` |
| 不回话 | `~/.dsh/bionic/ask.log` 有没有「看到提问 / 唤醒成功」；`session.id` 指向的会话还在不在 |
| OCR 搜不到 | 关键词要短（2~8 字）；OCR 有错字，匹配是模糊的 |

## 七、怎么改

```powershell
# 1. 改源码（这个仓库）
#    JS:    src/*.js
#    窗口:   examples/floating-chat/window.py

# 2. 同步进 DSH
node scripts/install-dev.mjs

# 3. 生效方式
#    JS 改动   → 重启 DSH
#    窗口改动  → 关掉窗口再开（独立进程，不用重启 DSH）
```

**注意**：`install-dev` 是「先删后拷」整目录同步。直接改
`~/.dsh/profiles/desktop/node_modules/dsh-bionic-intelligence/` 里的文件，跑一次同步就没了。

## 附：会话钉与防归档

插件的提问窗**只叫醒一个会话**，写在 `~/.dsh/bionic/pin.session`：

```
5e401283-336d-841b-a701-168a63a69bd0
```

- 钉住后，任何其他会话的 `session/event` 都不能把它顶掉（`rememberSession` 直接忽略）。
- 每次叫醒前跑一次 **会话保护**：`workspaceRegistry.unarchiveSession` → `pinSession`。
  顺序不能反 —— 归档会顺带清掉 pin。
- 为什么要它：已归档会话会被 `ArchivedSessionGate` 在每一步 reject，消息被丢弃，
  用户侧就是"它彻底不理我"（QQ 那边踩过同一个坑，见 `qqbot-workspace/session-whitelist.json`）。
- 换会话：改 `pin.session` 后重启 DSH。
